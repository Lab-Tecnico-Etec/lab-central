## Padrões de colaboração

- Use branches com nomes descritivos, como `feat/nova-funcionalidade`, `fix/correcao` e `docs/atualizacao`.
- Faça mudanças pequenas e documentadas; abra Pull Requests para revisão sempre que possível.
- Execute testes e builds disponíveis antes de solicitar revisão e informe o que realmente foi executado.
- Nunca envie credenciais, tokens, chaves privadas, dados pessoais ou arquivos `.env` reais.
- Defina a licença de cada projeto de forma explícita com os responsáveis; não presuma que o código está liberado para reutilização.

## Como adicionar um projeto ao catálogo

Abra uma issue ou Pull Request atualizando a tabela acima com:
1. Nome e link do repositório.
2. Objetivo em uma frase.
3. Categoria e tecnologias principais.
4. Estado atual e responsável, se definido.

## Limites atuais

Esta central documenta padrões recomendados. Ela não altera automaticamente permissões, equipes, regras de branch, configurações de segurança ou deploy da organização. Essas configurações devem ser revisadas com os administradores e ajustadas conforme as necessidades reais de cada projeto.
