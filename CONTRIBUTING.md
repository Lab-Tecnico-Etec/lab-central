# Guia de contribuição — Lab Técnico ETEC

Obrigado por contribuir com os projetos do Lab Técnico ETEC.

## 1. Antes de começar
- Leia o README do repositório em que pretende trabalhar.
- Confira as issues abertas e evite duplicar trabalho.
- Em caso de dúvida, abra uma issue antes de fazer mudanças grandes.
- Nunca publique senhas, tokens, chaves de API, dados pessoais ou arquivos de configuração com segredos.

## 2. Fluxo recomendado
1. Crie uma branch a partir de `main` com um nome descritivo:
   - `feat/nome-da-funcionalidade`
   - `fix/resumo-do-problema`
   - `docs/assunto-da-documentacao`
   - `chore/ajuste-tecnico`
2. Faça alterações pequenas e focadas.
3. Execute os testes, verificações e builds disponíveis no projeto.
4. Atualize a documentação quando o comportamento ou a instalação mudar.
5. Abra um Pull Request descrevendo o problema, a solução, os testes executados e eventuais limitações.

## 3. Commits
Use mensagens curtas e claras, preferencialmente no padrão:
- `feat: adiciona busca de projetos`
- `fix: corrige validação de formulário`
- `docs: atualiza instruções de instalação`
- `refactor: simplifica serviço de dados`
- `test: adiciona testes de validação`
- `chore: organiza configuração`

## 4. Qualidade
- Preserve o estilo e a arquitetura existentes.
- Não inclua dependências sem justificar a necessidade.
- Não remova funcionalidades ou dados sem discussão prévia.
- Registre passos para reproduzir bugs e inclua evidências quando forem úteis.
- Não declare testes como aprovados se não foram executados.

## 5. Pull Requests
- Mantenha o escopo do PR pequeno.
- Relacione issues usando referências como `Fixes #12`, quando aplicável.
- Informe mudanças visuais com capturas de tela, quando apropriado.
- Aguarde revisão antes de mesclar, especialmente em mudanças que afetam dados, segurança ou deploy.

## 6. Projetos escolares
Respeite os critérios acadêmicos aplicáveis, identifique claramente protótipos e limitações e não publique dados de estudantes, professores ou da instituição sem autorização.
